## 🌐 What Is GitHub Pages?

GitHub Pages is a free hosting service that publishes static websites directly from a GitHub repository.

Think of it as a bridge between website code and a live website.

**How it works:**

1. **Website code:** Files such as `index.html`, `style.css`, and `script.js` define the website.
2. **GitHub repository:** Stores the project's files online.
3. **GitHub Pages:** Publishes the static files from the selected branch and folder.
4. **Live website:** Visitors can access the published website through a public URL.

### GitHub vs. GitHub Pages

| GitHub | GitHub Pages |
|---|---|
| Stores project files and source code | Publishes the website online |
| Displays files, folders, and commit history | Displays the rendered website |
| Useful for collaboration and version control | Useful for sharing a live static website |

For this project:

- **Repository:** https://github.com/Tanvi-1496/tanvi-interactive-portfolio
- **Live website:** https://tanvi-1496.github.io/tanvi-interactive-portfolio/

These are different links. The repository shows the code, while the live URL shows the website visitors see.

### Why Is GitHub Pages Useful?

- **Free hosting:** No paid web server is required for a basic static site.
- **Simple deployment:** The website can be published from a GitHub branch.
- **Portfolio building:** Projects can be shared through a live URL.
- **DevOps fundamentals:** It introduces version control, deployment configuration, and publishing workflows.

**Important limitation:** GitHub Pages is designed for static websites. It does not run a traditional server-side backend or database application.

## 🚀 Deployment Process

The website was deployed using the following steps:

1. Created the website using HTML, CSS, and JavaScript.
2. Added the website files to a GitHub repository.
3. Uploaded the required image assets.
4. Opened **Settings → Pages** in the repository.
5. Selected **Deploy from a branch** as the publishing source.
6. Selected the `main` branch and `/(root)` folder.
7. Saved the configuration and waited for deployment.
8. Opened the published website and verified that it was accessible.

The site is published at:

## 📁 What Is `.gitkeep`?

Git tracks files, not empty directories. An empty folder created on a computer generally will not appear in a Git repository.

A `.gitkeep` file is a commonly used placeholder that allows an otherwise empty directory to be represented in the repository.

For example:

**Before:**

```text
assets/
```

An empty folder has no files for Git to track.

**After:**

```text
assets/
└── .gitkeep
```

Now Git can track the placeholder file and, therefore, represent the directory.

### Do We Still Need `.gitkeep`?

Once `assets/` contains `tanvi-portrait.png`, the image itself is enough for Git to track the directory. The `.gitkeep` file is no longer necessary there, although leaving it does no harm.

The same principle applies to the `screenshots/` folder: after the actual PNG screenshots are uploaded, its `.gitkeep` file can remain or be removed.
